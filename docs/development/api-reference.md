# API Reference

Wits Quest exposes a **hand-written REST API** (Express + TypeScript) plus a **Socket.IO WebSocket layer** for real-time PvP. Supabase is used strictly as a server-side database and storage layer — it is never exposed to the frontend, and no API endpoints are generated by a backend-as-a-service — satisfying the course brief's hand-written API requirement.

- **Base URL (development):** `http://localhost:3000`
- **Base URL (production):** `https://wits-quest-backend.onrender.com` — deployment in progress (fix F47)
- **Content type:** `application/json`
- **Authentication:** Bearer JWT in the `Authorization` header (7-day expiry), issued on login/registration

Endpoint status legend:

- ✅ — implemented and verified live against the running backend + Supabase
- ◐ — implemented per the code audit; not yet re-verified live
- ⚠ — implemented but has a known tracked defect (fix ID in brackets, see the *Master Fixes & Outstanding Features Worklist*)

## Async PvP — `/api/battle/async`

All routes behind `authMiddleware`. The full lifecycle is a 6-status state machine:
`PENDING_ACCEPTANCE → CHALLENGER_TURN / DEFENDER_TURN → COMPLETED / EXPIRED / DECLINED`.

| Method | Path | Auth | Purpose | Status |
| :--- | :--- | :--- | :--- | :--- |
| GET | `/api/battle/async/opponents` | JWT | Every other registered student (public fields only) for the challenge picker. | ✅ |
| GET | `/api/battle/async/my-matches` | JWT | Matches bucketed into **Your Turn / Waiting / Challenges / History**; lazily expires stale challenges on read. | ✅ |
| GET | `/api/battle/async/:id` | JWT | Full match detail for the play-turn view. Returns `yourDeck` and `usedCardIds`; only reveals **your** current card — never the opponent's in-flight card. | ✅ |
| POST | `/api/battle/async/challenge` | JWT | `{ defenderId }` — snapshots both default decks, sets 24 h `expiresAt`, status `PENDING_ACCEPTANCE`. Rejects a duplicate active challenge in either direction (409). | ✅ |
| POST | `/api/battle/async/:id/accept` | JWT | Defender accepts; flips to `CHALLENGER_TURN`. | ✅ |
| POST | `/api/battle/async/:id/decline` | JWT | Defender declines; terminal status `DECLINED`. | ✅ |
| POST | `/api/battle/async/:id/play-turn` | JWT | `{ cardId, stat }` — only the side whose turn it is may call. The server resolves both sides' cards and the round via `battleResolution.ts`; on match decision it runs `applyMatchResult` for both sides and returns a `matchEnd` reward object. | ✅ |

Design notes:

- **Turn state is derived, not stored.** Whose turn it is and each side's per-stat quota are recomputed from `roundsHistory` on every read (`asyncChallengeState.ts`), eliminating a class of stored-state drift bugs.
- **24-hour expiry is lazy-checked**, on every read — a lapsed invite expires with no forfeit; a match already underway forfeits to the side *not* holding the pick.
- The client **only ever sends a card + stat choice** — never a claimed result.

## Live PvP — Socket.IO events

Transport: Socket.IO over the same server. The server is authoritative: it fetches both real decks itself, resolves every round, and rejects invalid picks.

**Client → server**

| Event | Payload | Purpose |
| :--- | :--- | :--- |
| `join_battle` | `matchId`, `userId` | Join the shared lobby / resume a match. No deck is trusted from the client — the server fetches it. |
| `submit_turn` | `cardId`, `stat` | The current picker's move. Only the picker's submission is accepted. |
| `set_active_card` | `cardId` | Change which of your cards is "up" when you're not the picker. |

**Server → client**

| Event | Payload | Purpose |
| :--- | :--- | :--- |
| `battle_start` | real deck | Both sides' resolved decks (to each their own). |
| `turn_state` | `isYourTurn`, `pickerUsername`, `turnEndsAt`, `roundNumber` | Emitted whenever the picker changes; drives the synchronized countdown. |
| `round_outcome` | shared `stat`, `wasYourPick`, `autoPicked`, outcome, category edge | Round reveal. |
| `battle_end` | result + rewards | Final result with XP/Essence/Elo changes. |
| `player_disconnected` / `player_reconnected` | — | Connection status; a disconnect starts a 60 s grace window, after which the match is forfeited. |
| `turn_error` / `join_error` | message | Rejections (not your turn, quota-locked stat, repeated card, no saved deck). |

Server-enforced rules: alternating picker (win keeps the pick, tie holds, loss flips), **30-second turn timer** that auto-picks on expiry, no-repeat cards with hand replenishment, 2-use-per-stat quota, first-to-3 within 5 rounds.

## Known API-level defects

The security and integrity gaps flagged ⚠ above are tracked with evidence and fixes in the [Fix Register](fix-register.md). The highest-priority items:

- **F1** — no server-side location verification on trivia attempts (the 25 m Haversine gate is client-only)
- **F2** — CPU battle outcomes are client-declared
- **F3/F4** — unauthenticated/legacy inline routes shadow the protected route files
- **F5** — no ADMIN/LECTURER role guard on authoring endpoints
- **F6** — repeat-answer card farming
- **F7** — real credentials published in the Render deployment doc (rotation required)

PvP routes (`/api/battle/async/*`, Socket.IO) already follow the target pattern — authenticated, server-resolved, client sends choices only — and are the reference implementation for the server-authority migration of the rest of the API.
